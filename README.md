# FetalCardio

Учебное PWA-приложение по фетальной эхокардиографии: стандартные срезы со схемами, алгоритмы «от находки к диагнозу», атлас ключевых ВПС, тест.

Автор: Жумагулов Н.М., врач ультразвуковой диагностики.

Сайт: https://jumagulovnm2016-ai.github.io/fetalcardio/

## Структура

| Файл | Что внутри |
|---|---|
| `data/meta.js` | Название, версия, автор, категории пороков |

| `data/quiz.js` | Вопросы теста (`a` — номер верного варианта, счёт с 0) |

| `search.js` | Поиск: ё/е, регистр, синонимы, аббревиатуры, все поля |

| `tests/` | Автоматические тесты |

## Медицинский контент

- Все срезы, алгоритмы и карточки имеют `status: "draft"` до экспертной проверки.
- `status: "approved"` валидатор принимает только вместе с `reviewedBy` и `reviewedAt` (ГГГГ-ММ-ДД).
- Источники в карточках пока указаны на уровне всей карточки (`section: "card"`, `verified: false`): это документы по теме, их соответствие конкретным утверждениям не сверено. После сверки укажите конкретный раздел (`def`, `keys`, `ddx`, `assoc`, `pitfalls`, `prognosis` …) и `verified: true`.
- Каждый источник в `data/references.js` сверен с записью PubMed (PMID и DOI).

## Библиотека эхограмм

Раздел `#/images`, снимок — `#/img/<id>`. На страницах пороков и срезов — блок «Эхограммы из открытых источников» со снимками, у которых в `cards` есть `chd:<id>` или `view:<id>`.

- Источники снимков: рисунки из статей открытого доступа под **CC BY** (Europe PMC) и файлы **Wikimedia Commons** (CC BY, CC BY-SA, CC0, общественное достояние). Рисунки с пометкой «reproduced/adapted from» не берутся: на них лицензия статьи не распространяется.
- `caption` — оригинальная подпись автора, без изменений. `captionRu` — перевод на русский: **черновик до экспертной проверки**, термины приведены к сокращениям карточек (АВСД, ТМА, DORV, СГЛОС…). В приложении перевод показан первым, оригинал — под ним. У снимков Nevit Dilmen описания среза нет: они только в библиотеке.
- `source` — атрибуция изображения (автор, статья, рисунок, DOI, лицензия). Это **не** источник медицинских утверждений карточки — такие источники только в `data/references.js`.
- Привязка к карточкам и разделы библиотеки — `status: "draft"` до экспертной проверки.
- CC BY-SA: изменённую версию снимка (стрелки, подписи, кадрирование) распространять под той же лицензией.
- Снимки не входят в предзагрузку service worker: кэшируются при первом просмотре в отдельный кэш `fetalcardio-img-v1`. Заменённый снимок кладите под новым именем.
- Добавить снимок: файл в `img/` (латиница, до 2 МБ) → запись в `data/images.js` → `npm test` и `tests/e2e.py`.

## Анатомический атлас

Раздел `#/atlas`. Каждая схема — отдельный SVG в `atlas/` и запись в `data/anatomy.js`.

- В SVG структуры сгруппированы по слоям (`<g id="layer-…">`), у каждой структуры и её подписи есть `data-s="<key>"` — по нему легенда подсвечивает структуру на схеме.
- Цвета берутся из CSS-переменных `--sv-*` (светлая и тёмная тема); при открытии SVG отдельно используются значения по умолчанию.
- Все схемы — `status: "draft"` и плашка «DRAFT · REQUIRES EXPERT REVIEW» до проверки врачом-экспертом. Пункты, требующие проверки, перечислены в поле `review`.
- Добавить схему: SVG в `atlas/` → запись в `data/anatomy.js` → путь в `FILES` в `sw.js` (и поднять `VERSION`) → `npm test` и `tests/e2e.py`.

## Доступ курсантов

Как в Академии УЗИ, но **отдельный проект Supabase**: аккаунты Академии сюда не пускают, и наоборот.
Вход по логину и коду от преподавателя или регистрация по почте с подтверждением. У каждого курсанта свой срок доступа.
Один аккаунт курсанта — одно устройство. Без входа приложение закрыто полностью.

Проект Supabase: организация **Fetalcardio**, адрес `https://xzmfcsmmbfgzyzifpnxx.supabase.co` (вписан в `account.js`). Если очистить `CONFIG`, закрытие выключится.

Настройка (один раз):
1. supabase.com → New project (имя `fetalcardio`, регион — ближайший). На бесплатном тарифе не больше 2 активных проектов.
2. Authentication → Sign In / Providers → Email: **выключить** «Confirm email».
3. SQL Editor → New query → вставить `supabase/setup.sql` → Run.
4. Edge Functions → Deploy a new function → имя `teacher-admin` → вставить `supabase/functions/teacher-admin/index.ts` → Deploy. В настройках функции выключить **Verify JWT with legacy secret** (функция сама проверяет, что её вызывает преподаватель). Если функция пишет, что нет ключа: Edge Functions → Secrets → `SERVICE_KEY` = Secret key (`sb_secret_…`).
5. Project Settings → API: Project URL и Publishable key вписать в `CONFIG` в `account.js`, поднять `VERSION` в `sw.js`, опубликовать.
6. Открыть сайт → Личный кабинет → Регистрация по своей почте → SQL Editor → `supabase/make-teacher.sql` → Run.

Секретный ключ (`sb_secret_…`) никогда не вписывается в файлы сайта — только в Secrets функции.

Ограничение: закрытие работает на уровне интерфейса. Посторонний не увидит приложение, но файлы сайта (`data/*.js`) и репозиторий на GitHub публичны.

## Проверка

```bash
npm test                       # контент, ссылки, ID, ответы теста, поиск, прогресс, SW
npm run validate               # только проверка контента
python3 -m http.server 8765 &  # затем браузерная проверка (нужен Playwright):
python3 tests/e2e.py           # все страницы × 3 ширины × 2 темы, офлайн, экспорт/импорт
python3 tests/auth_e2e.py      # закрытый доступ с имитацией Supabase: вход, срок, одно устройство, офлайн
```

Перед публикацией изменений контента запускайте `npm test`. При изменении списка файлов обновите `FILES` и `VERSION` в `sw.js`.
